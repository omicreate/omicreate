# またね帳（プロトタイプ）

個人美容師（1人サロン・フリーランス・業務委託・シェアサロン）のための「再来ノート」です。
会計のときに次回の目安を残しておくと、声をかけてもよさそうなお客様を数人だけ示します。文面は自分で直して、自分で送ります。
スマホのブラウザで動くアプリ（PWA）で、記録はその端末の中だけに保存されます。

> 試作の段階です。実際の美容師さんに使ってもらう前の確認用で、まだ公開していません。

## 主な機能

- **ホーム**: 今日のお客様（前回のメニューとレシピのメモ）／予約日を過ぎた人の「来た？」確認／声をかけてもよさそうな人（最大5人）／出していない人の理由の要約
- **来店記録**: 今日のお客様の［来た］→［6週］→［保存］の3回で記録。1行入力（例「ゆず カットカラー 6週」）、前回と同じメニュー、入力途中の自動保存、削除の10秒取り消し
- **またねカード**: 記録のあと「次回の目安：12月中旬ごろ」と予約リンクの入った文面を、LINE で送るかコピー
- **声かけ**: 「いつもは約8週ごと → 今回は11週」の根拠と、記録上の最終来店日を最上部に表示。［実は来ていた］でその場で直せる。送ったあと30日は候補に出さない
- **再来ボード**: 稼働顧客数・次回の約束・声かけと戻りの3つの数字だけ（金額やパーセントは出さない）
- **データ**: 暗号化バックアップ（パスフレーズ）と復元、PIN ロック、サンプルデータで試す

## 使い方

1. ページを開き、最初の画面の「3つの約束」を読んで［読みました］に印を付けます。
2. ［サンプルで試す］で架空のお客様10人の例を見るか、［自分のお客様で始める］で自分の名前・予約リンク・メニューを入れて始めます。
3. 来店のたびに記録し、週に1回ほどホームの「声をかけてもよさそうな人」を見て、必要なら［声をかける］から文面を直して送ります。
4. 設定 → データ から、ときどき暗号化バックアップを書き出してください（端末が壊れると記録は戻せません）。

## データ/プライバシー

- アカウント登録はありません。
- 記録は使っている端末のブラウザの中（IndexedDB）にだけ保存します。サーバーはありません。
- 外部への送信・外部API・アクセス解析・Cookie はありません。ビルドしたページには、自分のサイト以外に通信できない設定（Content-Security-Policy）を入れています。外とやりとりするのは、利用者が自分で押す［LINEで送る］［コピー］と、ファイルの書き出し・読み込みだけです。
- 電話番号・メールアドレス・住所・生年月日の欄はありません。お客様は呼び名で記録します。
- 所属サロンから引き継いだお客様や、サロンの集客で来たお客様は「所属サロンの顧客」として、声かけ候補と平文の書き出しから外します。
- アレルギーなどの健康情報は記録しない設計です。メモに健康に関わる言葉が入ると注意を出します。カルテの代わりにはなりません。
- 作り手は記録を受け取らず、見ることもできません。

## 技術構成

- 実行方式: Vite + React + TypeScript の PWA（vite-plugin-pwa でオフライン対応）
- 保存: IndexedDB。バックアップは Web Crypto（PBKDF2-SHA256 → AES-GCM-256）で暗号化
- 主なフォルダ:
  - `src/domain/` 計算（来店周期・目安・声かけ候補・ボード・文面）。画面に依存しない
  - `src/storage/` 保存・暗号化・書き出し
  - `src/state/` `src/ui/` 画面
  - `e2e/` 受け入れテスト（仕様 9章の AC）
  - `docs/` 調査・構想の比較・仕様
- 外部ライブラリ: React、Vite、vite-plugin-pwa。テストに Vitest、Testing Library、fake-indexeddb、jsdom、Playwright

## 確認方法

```sh
cd prototypes/matane
npm install
npm test           # 単体テストと画面のテスト（Vitest）
npm run typecheck  # 型チェック
npm run e2e        # ビルドして、スマホ幅のブラウザで受け入れテスト（Playwright）
npm run dev        # 開発用サーバーで開く
```

2026-11-07 時点の結果: 単体テスト 272件、E2E 21件がすべて通過。
