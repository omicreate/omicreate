## 2. 直さなかった指摘

- 来店日が過去の記録でまたねカードを出さない（上の表のとおり意図した動き）
- OS の文字サイズ設定に合わせて文字が大きくならない。全体の px を rem に置き換える必要があり、実機で確かめてから決める

## 3. 未検証のこと

- iPhone（Safari・ホーム画面に追加した状態）と Android の実機での動作。確かめたのは Playwright の Chromium だけ
- 日付欄の表示順（Chromium のテスト環境では月/日/年の順に出た。日本語設定の端末なら年/月/日になるはず）
- 下書きの「画面を離れる瞬間の保存」（pagehide）。0.3秒後の自動保存は E2E で確認済み
- 暗号化バックアップの 600,000 回の鍵の計算が、性能の低いスマホで何秒かかるか（処理中の表示は入れてある）
- 更新が入るとページが自動で読み込み直される（入力途中の内容は下書きとして残る）。読み込み直す前に聞くかは未決
- 来店記録が二重入力でも続くか（仕様 11章の最大の未検証の前提。試用で測る）

## 4. 追加: 予約を入れる（S10）

仕様 0.1版にない追加（2026-11-11）。会計のあとで Instagram・LINE・電話で入った予約や、新しいお客様の予約を、美容師が自分のために手入力する。自動では取り込まない。

- 入り口: ホームの［来店を記録］の下の控えめなボタン［予約を入れる］、顧客カードの「予約」欄（［予約日を入れる］／［予約日を変える］［予約を取り消す］）、`#/booking?c=<顧客ID>`
- 客を選ぶ: 来店記録と同じ部品（最近のお客様・呼び名の頭文字で検索）。新しいお客様はその場で呼び名・データの管理者・獲得経路を入れて登録する（来店記録の新規客と同じ必須ルール）。来店記録は作らない
- 日付の欄: 1つの欄で貼り付け・入力・キーボードの音声入力を受け、読み取った日付を「11月20日（金）」と出す。すぐ下の日付ピッカーで確かめ・上書きできる。読み取りは `src/domain/bookingDate.ts` の `parseBookingDate(text, today)`
- 保存するのは日付と入れた日時だけ（`Customer.booking = { date, setAt }`）。貼った文は画面の中だけに持ち、下書き・URL・保存のどこにも出さない（E2E で IndexedDB と localStorage を確かめている）
- 有効な予約は `src/domain/booking.ts` の `effectiveOpenBooking` 1か所で決め、区分・今日のお客様・来た？・声かけ候補・顧客カード・まとめ記録はすべてこれを使う。ボードの「次回の約束あり」は来店記録の next で数えるまま
- 片付け: 入れた日以降の来店を保存すると消える（まとめ記録も同じ）。来た？・まとめ記録の［来なかった］で消える。顧客カードの［予約を取り消す］で消える（10秒取り消せる）
- 会計時に入れた予約がある客に［予約を入れる］で別の日を入れると、その来店記録に `bookingResolution: 'replaced'`（予約日を変えた）の印を付けて片付ける。あとから入れた予約を取り消したり［来なかった］にしても、古い予約は戻ってこない。会計時の予約を顧客カードで取り消すと `'cancelled'`（取り消した）の印。どちらも next はそのまま残すので、ボードの「次回の約束あり」の数は変わらない
- バックアップ・復元・平文 JSON は booking をそのまま通す。古いバックアップ（booking なし）も読める。形が壊れていれば「壊れたファイル」として読まない

### 決めたこと（仕様にない決め事）

| 決めたこと | 理由 |
|---|---|
| 「入れた日以降の来店記録」は、入れた日より後の日付の記録と、同じ日付で予約を入れたあとに作った記録とする（同じ日に予約より前に作った記録では無効にしない） | 会計で記録したあと、その日の夜に LINE で入った予約が、すぐ無効にならないように |
| 年のない日付（11/20・11月20日）は今年。今日より前なら、来年のその日が半年（183日）以内のときだけ来年（11月の「1月10日」）。それ以外（11/7 の「11月1日」）は過去のエラー。今年でない日付は「2027年1月10日（日）」と年をつけて出す | 打ち間違い・聞き間違いが、気づかないまま約1年先の予約にならないように |
| 「20日」で今月にない日（11月の31日など）は来月以降で最初にある月。「今月20日」「来月20日」「再来月10日」は月を決めて読む。「再来週火曜」は来週の火曜の7日あと | ふつうの書き方を読めるように |
| 「3日後」「2週間後の火曜」「先週の火曜」「先月の20日」「来週あたり」のような数えて決める言い方は読めない扱いにしてカレンダーへ促す | 「10日後」を10日と読むなど、別の日を注意なしに入れないように |
| 欄に読めない文を入れ直したら、前に読み取ってカレンダーに入れた日付を消す（カレンダーで選び直すまで保存できない） | 画面に「読み取れませんでした」と出ているのに、古い日付で保存されないように |
| 「(金)」のような括弧だけの曜日や、日付のすぐ後の「金曜日」は添え書きとして日付に数えない。同じ日付の言い換え（明日（11月8日））は「2つ」と数えない | 予約の返事によくある書き方で、毎回「2つありました」と出ないように |
| 「あす」「きょう」は読まない（今日・本日・明日・あした・明後日・あさって だけ） | 「ございます」などの文中の語を日付と読み違えないように |
| 予約日を変えるときの「11月4日の予約を11月20日に変えます」は、保存ボタンの上に出し続ける（確認の画面は挟まない） | 保存前に必ず目に入り、タップを増やさないため |
| 会計時に入れた予約も顧客カードの［予約を取り消す］で取り消せる。来店記録の next は書き換えず、`bookingResolution` に印を付けるだけ（10秒取り消せる） | ボードの「次回の約束あり」の数を変えずに、予約だけを片付けるため |
| CSV では、あとから入れた予約を「来店日が空で、次回が『予約 2026-11-20（あとから入れた予約）』の1行」として、その客の来店の行のあとに出す（列は増やさない） | 既存の列の並びを変えず、来店記録のない新しいお客様の予約も書き出せるように |
| 予約を保存したあと10秒間は取り消せる（新しいお客様はその人ごと消える） | 来店記録の削除などと同じ取り消しの仕組みに合わせた |
| 今日のお客様で来店記録のない人は「はじめてのご来店」と出す | 前回の欄が空だと、記録が消えたように見えるため |

### やらないこと

- 予約の自動取り込み（LINE・Instagram・予約サイト・カレンダーとの連携）
- 時刻の保存、予約の枠、重なりの確認
- 予約の変更履歴（変えたら上書き）
- 貼った文やメッセージの保存
