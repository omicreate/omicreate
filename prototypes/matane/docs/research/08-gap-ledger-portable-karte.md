## 1. 結論（要点）

1. **予約を一つの台帳にまとめること自体はできる。ただし、経路ごとに「正規の取り込み口」の有無がはっきり分かれる。**
   - LINE と Instagram には公式 API がある。
   - minimo には公式の外部連携があるが、連携先は8社に限られる。
   - HPB／SALON BOARD については、公開APIの資料が見つからなかった。既存の連携ツールの一部は、SALON BOARD のパスワードを預かって画面を読み取る方式とみられる（estimate）。
   - したがって新アプリの初期版では、①通知メールの転送と解析、②素早い手入力、③LINE の Webhook、の3つで台帳を作るのが現実的である。
2. **「美容師が持ち出せるカルテ」は、顧客ごとに「誰が集客したか」「誰がデータの管理者か」を記録すれば、法的に説明しやすくなる。**
   - 本人のSNS・本人の minimo・本人の LINE で獲得した顧客は、美容師自身が個人情報取扱事業者として取得したと整理しやすい。
   - サロンの HPB 掲載で獲得した顧客や、サロンから引き継いだ顧客は、持ち出すと①〜③のリスクが重なる。
3. **2026年7月17日に公布された改正個人情報保護法（令和8年法律第56号）で、新30条の3が加わった。**
   - 受託者は、委託を受けた業務に必要な範囲を超えて個人情報を扱ってはならない、と明文で定められた（fact、施行日は未確認）。
   - 業務委託美容師がサロンの顧客データを「委託先」として扱っていた場合、それを独立後に使うことは法律上も明確に禁止される方向になる。

## 3.（B）法務：持ち出しが問題になる条件

### 3-1 三つの法的枠組み

**① 不正競争防止法（営業秘密）**
- 定義（2条6項）:「秘密として管理されている…事業活動に有用な…営業上の情報であって、公然と知られていないもの」（fact、e-Gov、2026-05-21施行版）。
- 示された営業秘密を「不正の利益を得る目的で、又は…損害を加える目的で」使用・開示すると不正競争になる（2条1項7号、fact）。
- 刑事罰は「十年以下の拘禁刑若しくは二千万円以下の罰金」（21条、fact）。
- 経産省『営業秘密管理指針』は、秘密管理性について「秘密管理意思が秘密管理措置によって従業員等に明確に示され、認識可能性が確保される」ことを求めているとされる。ただしサイトが403で、本文と最新の改訂日を確認できなかった（**unverified**）。

**② 個人情報保護法**
- 個人情報データベース等を事業に使う者は、規模にかかわらず個人情報取扱事業者になる（16条2項、fact）。
- 主な義務（いずれも fact）:
  - 目的外利用の禁止（18条）
  - 不正な手段による取得の禁止（20条1項）
  - 同意のない第三者提供の禁止（27条1項）。ただし委託・事業承継・共同利用の場合は「第三者に該当しない」（27条5項）
- 従業者・元従業者が、業務で扱った個人情報データベース等を不正な利益を図る目的で提供・盗用すると、「一年以下の拘禁刑又は五十万円以下の罰金」（179条、fact）。
- 改正法の新30条の3により、受託者は委託された業務に必要な範囲を超えて扱えなくなる（fact。令和8年法律第56号、公布2026-07-17。施行日は未確認）。

**③ 契約（競業避止・引き抜き禁止）**
- 弁護士Q&Aでの回答傾向（fact：相談サイト上の回答。法的な判断ではない）:
  - 顧客からの問い合わせに応じるだけなら問題になりにくいが、積極的に勧誘すると問題になりうる（2019）。
  - 次の勤務先を具体的に伝えて来店を勧めると、トラブルになりうる（2022）。
  - 損害額は、立証が難しいため少額になることが多い（2022）。
  - 業務委託契約で無断連絡を禁止していた事例で、顧客情報を秘密情報とし、無断利用を不法行為とみる回答があった（2019）。
- 業務委託の相手（雇用ではない）に広い競業避止を課すと、職業選択の自由や独占禁止法（優越的地位の濫用）の面から効力が制限されうる、との指摘がある（**unverified**。公取委サイトは他レポートでも403）。

### 3-2 立場ごとの整理（estimate）

| 働き方 | 顧客との契約主体と集客 | 個人情報保護法での位置づけ（推定） |
|---|---|---|
| 業務委託（サロンの屋号・サロンのHPB・サロンのレジ） | サロン | 顧客データはサロンの個人データ。美容師は「従業者」（24条）または「委託先」（25条、改正後は30条の3）にあたる。独立後に使うと、目的外利用や第三者提供の問題になり、営業秘密や契約違反にもなりうる |

| 問題になりにくい | 危ない |

## 4. アプリの規約と画面に入れるべき仕組み（提案）

1. **顧客ごとの「獲得経路」と「獲得者」**
   - 登録時に必須とする。選択肢は「本人SNS／本人minimo／本人LINE／紹介／サロン媒体（HPB等）／サロンからの引き継ぎ／不明」。
   - 予約の取り込み元から自動で推定する。サロン名義の HPB メールから取り込んだ場合は「サロン媒体」にする。
2. **「データの管理者」欄**
   - 「美容師本人」か「所属サロン（委託元）」かを記録する。
   - サロン管理の顧客は、初期設定でエクスポートと一斉配信の対象から外す。
3. **退店モード**
   - 契約の制約を入力するチェックリストを用意する（競業避止の期間・地域、非勧誘、持ち出し禁止）。
   - 制約期間中は、サロン由来の顧客への一斉配信を止める。届いた問い合わせへの返信だけを許す。
4. **同意の取り直し**
   - 退店や独立の前後に、顧客へLINE・SMS・QRで同意ページを送る（例：「○○が新しい店でもカルテを使ってよいですか」）。
   - 同意した顧客だけを移す。同意の日時と文面のバージョンを記録する。
   - 同意のない顧客のデータはロックし、期限が来たら削除する。
5. **顧客が持つカルテ（共有型）**
   - 顧客自身がカルテを持ち、担当の美容師に閲覧を許可する方式も選べるようにする。
   - 法33条の電磁的開示で、サロンのデータを顧客経由で持ち込めるようにする。
6. **取り込みの安全策**
   - SALON BOARD の ID／パスワードは預からない。
   - サロン名義の CSV を取り込むときは警告を出し、「正当な権限がある」ことの確認を求める。
7. **規約に入れる条項**
   - ユーザーは、登録データについて正当な権限を持つことを保証する。
   - 所属先との契約で制限されるデータは登録・エクスポートしない。
   - 当社は委託先として、データを二次利用・販売しない（改正30条の3に合わせる）。
